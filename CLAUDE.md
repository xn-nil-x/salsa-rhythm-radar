# CLAUDE.md — правила разработки Salsa Rhythm Radar

## Команды

```bash
npm run dev        # dev-сервер, http://localhost:5173
npm test           # Vitest (Node): DSP, эталоны, сквозные метрики движка
npm run build      # tsc -b + vite build — должен проходить перед коммитом
npm run bench      # метрики трекера; результаты переносить в docs/EXPERIMENTS.md
npm run demo-wav -- out.wav 180 3-2 30
npm run guide      # пересобрать docs/user-guide.html (картинки встраиваются в base64)
```

Руководство пользователя существует в двух формах: `docs/USER_GUIDE.md` и `docs/user-guide.src.html`. При изменении UI обновлять обе. `docs/user-guide.html` не редактировать руками: это результат `npm run guide`.

## Принципы (из ТЗ §16, обязательны)

1. **Не имитировать анализ.** Анимация не подменяет измерение. Вне Demo нет случайных данных.
2. **Различать эталоны, наблюдения и гипотезы** — в данных (`kind`), цвете и подписях. Эталон никогда не выдаётся за распознанный инструмент.
3. **Частотный диапазон ≠ инструмент.** Не писать «распознана конга», если найдены атаки в 200–2000 Гц.
4. **Не скрывать неопределённость:** конкурирующие гипотезы темпа, уверенность, отсутствие захвата видны пользователю.
5. **Исходное время сохраняется** независимо от музыкальной сетки, без обязательной квантизации.
6. **Аудио не покидает устройство** без явного согласия.
7. **Модули заменяемы:** DSP — чистые функции и классы без Web Audio; движок тестируется в Node.

## Архитектурные соглашения

- Анализ живёт в `src/audio/analysis-engine.ts` (чистый TS) и запускается в Worker. Web Audio есть только в `audio-engine.ts` и `public/capture-worklet.js`.
- Время — аудиочасы в секундах (кадр / sampleRate). Фаза цикла — 0…1, 0 = счёт 1 сверху, рост по часовой стрелке.
- Эталоны задаются на сетке 32 шагов на 8 счетов (шестнадцатые). Шаг может быть дробным. Рисунки, зависящие от клаве, пишутся для одного направления и поворачиваются на полцикла.
- Каждый эталон обязан иметь `source` и `status` (`established` / `simplified` / `illustrative`). Новые рисунки проверять по источникам и вносить в `docs/PATTERNS.md`.
- При изменении алгоритма анализа поднять `ALGORITHM_VERSION` и перезапустить `npm run bench`.
- Высокочастотные данные (снимки 15 Гц, кадры 60 Гц) не кладутся в React state. Рендер читает `audioEngine.latest` в `requestAnimationFrame`, в zustand идёт только низкочастотная статистика.
- Код и комментарии — на английском, UI и документация — на русском. Строки интерфейса — через `src/i18n`.

## Тесты

- Любое изменение DSP или трекера сопровождается тестом на синтетическом сигнале с известным BPM и фазой (`src/audio/synth.ts`).
- Метрики, а не «красота»: ошибка BPM, ошибка фазы в мс, время захвата, точность накопления.
- Для отладки удобно временно создать `tests/debug.test.ts` с выводом временного ряда (не коммитить).

## Чего не делать

- Не подключать тяжёлые модели (source separation, распознавание инструментов) без замера производительности на телефоне.
- Не включать браузерные `echoCancellation` / `noiseSuppression` / `autoGainControl` для микрофона: они разрушают транзиенты.
- Не коммитить `In/` (исходные материалы владельца проекта) и `.env`.
