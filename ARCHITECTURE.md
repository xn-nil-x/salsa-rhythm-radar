# Архитектура

## 1. Место в более широкой системе

Salsa Rhythm Radar — музыкальная половина исследовательской системы из трёх частей:

| Часть | Что делает | Статус |
|---|---|---|
| **Rhythm Radar** (этот репозиторий) | Слушает музыку, оценивает темп и фазу, показывает полиритмию по восьмёркам | MVP 1 + основа MVP 2 |
| **Salsa Motion Lab** | Смартфон на пояснице (IMU: aₓ, aᵧ, a_z, ω): движение корпуса, предполагаемые переносы веса | вне MVP; есть шов `src/imu/types.ts` |
| **Salsa Alphabet** | Таксономия 46 движений, 8 семейств и 7 признаковых осей: опора, перенос веса, направление, положение ног, вращение, ритм, артикуляция | вне MVP; оси использованы в модели танцевальных событий |

Общая ось всех трёх частей — **музыкальная фаза восьмёрки**. Рисунки инструментов, наблюдаемые атаки, эталонные шаги и (в будущем) события IMU представлены как события с фазой 0…1 и исходной меткой времени, поэтому их можно накладывать на один циферблат и сравнивать.

## 2. Потоки данных и потоки выполнения

```
 main thread                         audio thread             worker
 ───────────                         ────────────             ──────
 mic (getUserMedia) ──┐
 <audio> (File) ──────┼──> AudioWorklet "srr-capture" ──port──> AnalysisEngine
 Demo AudioBuffer ────┘    (моно, блоки по 1024 + номер кадра)   │  hop 512: признаки, атаки,
        │                                                        │  огибающая 30 с → свёртка
        └──> динамики (только File/Demo)                         │  восьмёрки → темп, фаза, «1»
                                                                 │  hop 1024: FFT 2048 → лента
                                                                 │  ленты сворачиваются часами
 UI (React) <──────── снимки 15 Гц (transferable) ───────────────┘
 Canvas: стрелка 60 Гц по аудиочасам + сглаживание
```

- **Аудиопоток** только копирует сэмплы. Вся обработка идёт в Web Worker (`src/audio/analysis.worker.ts`), UI не блокируется.
- **Канал worklet → worker** — прямой `MessagePort`, минуя главный поток.
- **Снимки** (`EngineSnapshot`) содержат параметры часов, состояние трекера, новые атаки, плотности, байтовую картинку спектрограммы и статистику. Главный поток не пересчитывает анализ, а только экстраполирует фазу между снимками.
- `AnalysisEngine` написан на чистом TypeScript без Web Audio, поэтому тесты и бенчмарк гоняют тот же код в Node.

## 4. Время и часы

- **Единая временная база** — аудиочасы: `кадр / sampleRate` совпадает с `AudioContext.currentTime`. Время атаки сохраняется независимо от музыкальной сетки.
- **`Transport`** отображает время в доли: `beats(t) = beatRef + (t − tRef)·bpm/60`. Отдельное поле `offset` хранит, какая доля считается «1». Ручная установка «1» поэтому не мешает автоматическому трекингу.
- **Коррекции фазы не прыгают:** `setCorrection` ставит поправку в очередь, `advance` применяет её со скоростью не более `slewRate` долей в секунду. Смена BPM сохраняет непрерывность фазы.
- **Три режима часов:** `auto` (часы ведёт трекер), `manual` (свободный ход с ручным BPM) и `reference` (только Demo: истинный темп синтезатора). Трекер работает всегда, поэтому в Demo диагностика показывает его ошибку против эталона.
- **Стрелка** рисуется по времени того, что слышно сейчас (`getOutputTimestamp`; для микрофона — `currentTime`). Расхождение со снимком сглаживается: мелкие поправки смешиваются, крупные применяются сразу.

## 5. Темп и фаза

Подробное исследование с таблицами — [docs/research/TEMPO.md](docs/research/TEMPO.md).

1. **Огибающая атак** — сумма положительного потока лог-магнитуды по трём диапазонам, шаг 11,6 мс, хранится 30 с.
2. **Темп — иерархическая свёртка восьмёрки** (`src/dsp/folding.ts`, «лента, свёрнутая в трубку»). Огибающая сворачивается с пробным периодом C — длительностью целой восьмёрки. Гипотезы ранжируются на коротком окне (экспоненциальная память 1,5 восьмёрки), а победитель уточняется на **адаптивном глубоком** окне: от 1,5 до 6 восьмёрок, растёт на ¼ за обновление, пока ритм стабилен, и сразу сжимается при появлении конкурента. Чёткость — χ² epoch folding, нормированная на ожидание для шума. Правильная восьмёрка сворачивается чётко на всех метрических уровнях: C, C/2 (такт), C/4, C/8 (доля), C/16 (восьмая). Оценка — геометрическое среднее чёткостей по уровням: так отсекаются тресильо (120 вместо 180) и «3 такта» у потактовых рисунков. Поиск ведётся в полуинтервале октавы `[bpmLo, 2·bpmLo)`: грубая сетка 0,6%, уточнение пиков 0,08%.
3. **Уверенность** — чёткость (×N чётче шума) и отрыв от второй гипотезы. Уровни: надёжно (≥ 6 и ≥ 1,6), вероятно (≥ 4 и ≥ 1,3), неуверенно (≥ 2,5), нет ритма. Пороги откалиброваны на 203 проверках.
4. **Захват** — 2 согласованные оценки подряд (обычно на 4-й секунде).
5. **Сопровождение** — каждые 0,5 с. Если лучшая гипотеза в пределах 3% от текущей, темп *скользит* к ней (`glideBpm`, до 25%/с, без скачков). Другая гипотеза принимается, только если держится 2 обновления при отрыве ≥ 1,15, и тоже через глиссандо. Перестройка при смене темпа 180 → 170 занимает ~4 с.
6. **Точный период** — победитель уточняется статистикой Z²ₙ по моментам атак (16 гармоник цикла): она гладкая по периоду, без «ряби» дискретной огибающей.
7. **Фаза** — профиль (окно ≤ 3 восьмёрок), свёрнутый с текущим периодом, коррелирует со скелетом сальсы (конга + бас + колокол, с учётом направления клаве). Шаблон применяется, только если корреляция Пирсона r ≥ 0,35, иначе работает нейтральная гребёнка из 8 долей. Тонкий сдвиг (внутри ¼ доли) берётся из кругового среднего моментов атак на сетке восьмых; задержка детектора атак (2 мс) компенсирована. Мелкие ошибки корректируются сразу (0,6·ошибки, с ограничением скорости). Переход на полдоли — только при свидетельстве ≥ 1,3 и 4 подтверждениях подряд.
8. **«1»** — положение шаблона даёт начало восьмёрки. Поворот выполняется через `glideOffset` после 3 согласованных оценок. Кнопка «Здесь 1» отключает автоопределение до его повторного включения в настройках.

## 6. Накопление — «лента»

Хранится не накопленная картинка, а **история во времени** (`src/accumulate/folded.ts`):

- `FrameHistory` — комплексные спектры (FFT 2048, шаг 1024, до 10 кГц, до 90 с, тихие кадры < −80 дБFS не сохраняются);
- список атак (время, канал, сила; до 90 с).

Изображение получается **сворачиванием ленты текущими часами**: фаза кадра — `frac(clock.cycleBeatsAt(t)/cycleBeats)`, вес — `exp(−возраст/(N·C))`, где N — память в восьмёрках (при «Мгновенно» — только последняя восьмёрка). Полная пересборка идёт 5 раз в секунду, новые кадры добавляются сразу. Когда PLL меняет темп, фазу или «1», вся накопленная картинка плавно сжимается, растягивается и поворачивается вслед за часами и **не стирается**. Сброс только по кнопке или при разрыве сигнала.

Полярная спектрограмма (`FoldedSpectrogram`):
- в каждой ячейке (A = 256 углов × бины частоты): W = Σw, P = Σw|X|², C = Σw·X·e^{+j2πkδ/N};
- δ — расстояние в сэмплах от центра кадра до центра ячейки: компенсация линейной фазой сохраняет когерентный режим;
- кадр делится между двумя соседними ячейками;
- отображение: **мощность** P/W; **когерентное** |C|²/W²; **когерентность** |C|²/(P·W) ∈ [0, 1] (≤ 1 по неравенству Коши — Буняковского);
- шкала в дБ относительно максимума мощности, общая для мощности и когерентного режима.

Плотность атак — то же сворачивание списка атак: 128 ячеек на цикл, линейное деление между соседями, без квантизации.

Рендер строит таблицу «пиксель → (слот, бин)» один раз на геометрию. Радиус переводится в частоту линейно `f = u·f_max` или логарифмически `f = 40·(f_max/40)^u`, где `u = (r − r₀)/(1 − r₀)`.

Два режима сворачивания (`tapeMode`):
- **refold** (по умолчанию) — вся лента сворачивается *одним* текущим периодом и фазой. Уточнение темпа выравнивает всю историю, настоящая смена темпа сначала размывает старую часть;
- **recorded** — у каждого кадра и атаки хранится номер доли, присвоенный часами при записи. Фаза равна `frac((beats + beatsBias + offset)/cycleBeats)`: смена темпа ничего не размывает, повороты «1» применяются ко всей истории, а `beatsBias` компенсирует перенумерацию при смене режима часов и Tap.

### Люминофор (отрисовка по умолчанию, 0.4)

Недостаток ленты — затухание по мощности при показе в дБ. Наблюдение возраста a весит `exp(−a/(N·C))`, но громкий бас, ослабленный до 5%, на шкале 60 дБ остаётся ярким: след гаснет ниже порога примерно за `N·ln10·range/10` восьмёрок (≈ 220 при N = 16), а на деле держится, пока кадр не уйдёт из 90-секундной ленты.

`PhosphorScreen` (`src/accumulate/phosphor.ts`) — экран ЭЛТ. Каждая ячейка хранит одно значение и при проходе стрелки обновляется по правилу `v ← v + (x − v)/N`:
- x — яркость нового кадра в той же шкале дБ, что и на экране (верх шкалы — бегущий пик мощности кадров, опускается на 1 дБ/с). Поэтому затухание `(1 − 1/N)` за оборот действует на видимую яркость, и погасший инструмент исчезает за ~3N оборотов при любом диапазоне;
- кадр делится между двумя соседними ячейками; шаг для кадра — `1 − (1 − 1/N)^(доля/кадров_на_ячейку)`, так что за полный оборот ячейка сдвигается ровно на 1/N, независимо от темпа;
- для когерентных режимов по тому же правилу обновляются P = ⟨|X|²⟩, C = ⟨X·e^{+j2πkδ/N}⟩ и вес W → 1; когерентность ρ = |C|²/(P·W), «когерентное» = яркость · ρ;
- тишина пишет x = 0: экран гаснет и в паузе;
- ячейки хранятся в координатах номера доли при записи; при показе экран поворачивается на `(beatsBias + offset)/cycleBeats`, поэтому смена «1» поворачивает картинку, а не портит её. Смену темпа люминофор не пересворачивает — как настоящий экран.

Память O(A·K) без истории, нет пересборки 5 раз в секунду. Лента продолжает записываться, так что переключение на «Ленту» показывает накопленную историю сразу.

## 8. Существенные решения

| Решение | Почему |
|---|---|
| Canvas 2D, а не SVG | Полярная спектрограмма — пиксельная карта (до 720² точек при 15 Гц); единая система отрисовки для слоёв и спектра |
| Анализ в Worker, worklet только копирует | Стабильность аудиопотока на телефонах; тот же код тестируется в Node |
| Собственная FFT вместо `AnalyserNode` | Нужны комплексные спектры для когерентного режима |
| Demo = чистый TS-рендер в буфер | Один и тот же сигнал в приложении и тестах; точный ground truth |
| Поиск темпа внутри октавы | Неоднозначность 90/180 явная и управляемая пользователем |
| Иерархическая свёртка целой восьмёрки вместо ACF доли | Темп верен во всех сценариях, захват 4 с; ACF давал 120 вместо 180 на клаве (измерено, research/TEMPO.md) |
| Фаза по скелету сальсы с проверкой r ≥ 0,35 | Снимает неоднозначность доля ↔ «&» (113 → 5 мс при джиттере); вне сальсы — нейтральная гребёнка |
| Лента + пересворачивание вместо накопления в ячейках | Картинка следует за PLL и не стирается при смене темпа и «1» |
| Люминофор (EMA яркости) как отрисовка по умолчанию | Затухание по видимой яркости: погасший инструмент исчезает за ~3N оборотов; лента в дБ держала след баса > 50 восьмёрок |
| Гистерезис доля ↔ «&» | В сальсе синкопы дают почти равный вес слабым долям (измерено) |
| Настройки в `localStorage` | Только удобство; библиотека шаблонов и сессии пойдут в IndexedDB (MVP 3–4) |
| Без внешних зависимостей DSP | Прозрачность алгоритмов, независимая замена модулей |
| `vite-plugin-pwa` не используется | Ручной `sw.js` + manifest без связки версий плагина |

## 9. Точки расширения

- **Сопоставление с рисунками (MVP 3):** фаза и «1» по скелету сальсы уже работают в трекере; `matchPattern` считает корреляцию отдельных эталонов. Дальше — вероятности по диапазонам, направление клаве по наблюдению, адаптивная глубина памяти темпа.
- **Запись и экспорт (MVP 4):** снимок уже содержит время, BPM, фазу, атаки с диапазоном и силой, версию алгоритма (`ALGORITHM_VERSION`).
- **IMU:** `src/imu/types.ts` — контракт данных и синхронизации двух телефонов.
- **Замена алгоритмов:** функции DSP чистые; движок вызывает их через узкие интерфейсы.
