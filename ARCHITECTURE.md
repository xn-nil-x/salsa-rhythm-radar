# Архитектура

## 1. Место в более широкой системе

Salsa Rhythm Radar — музыкальная половина исследовательской системы из трёх частей:

| Часть | Что делает | Статус |
|---|---|---|
| **Rhythm Radar** (этот репозиторий) | Слушает музыку, оценивает темп и фазу, показывает полиритмию по восьмёркам | MVP 1 + основа MVP 2 |
| **Salsa Motion Lab** | Смартфон на пояснице (IMU: aₓ, aᵧ, a_z, ω): движение корпуса, предполагаемые переносы веса | вне MVP; есть шов `src/imu/types.ts` |
| **Salsa Alphabet** | Таксономия 46 движений, 8 семейств и 7 признаковых осей: опора, перенос веса, направление, положение ног, вращение, ритм, артикуляция | вне MVP; оси использованы в модели танцевальных событий |

Общая ось всех трёх частей — **музыкальная фаза восьмёрки**. Рисунки инструментов, наблюдаемые атаки, эталонные шаги и (в будущем) события IMU представлены как события с фазой 0…1 и исходной меткой времени, поэтому их можно накладывать на один циферблат и сравнивать.

## 2. Потоки данных и потоки выполнения

```
 main thread                         audio thread             worker
 ───────────                         ────────────             ──────
 mic (getUserMedia) ──┐
 <audio> (File) ──────┼──> AudioWorklet "srr-capture" ──port──> AnalysisEngine
 Demo AudioBuffer ────┘    (моно, блоки по 1024 + номер кадра)   │  hop 512: признаки, атаки,
        │                                                        │  огибающая, темп, PLL
        └──> динамики (только File/Demo)                         │  слоты фазы: FFT 2048,
                                                                 │  полярная спектрограмма
 UI (React) <──────── снимки 15 Гц (transferable) ───────────────┘
 Canvas: стрелка 60 Гц по аудиочасам + сглаживание
```

- **Аудиопоток** только копирует сэмплы. Вся обработка идёт в Web Worker (`src/audio/analysis.worker.ts`), UI не блокируется.
- **Канал worklet → worker** — прямой `MessagePort`, минуя главный поток.
- **Снимки** (`EngineSnapshot`) содержат параметры часов, состояние трекера, новые атаки, плотности, байтовую картинку спектрограммы и статистику. Главный поток не пересчитывает анализ, а только экстраполирует фазу между снимками.
- `AnalysisEngine` написан на чистом TypeScript без Web Audio, поэтому тесты и бенчмарк гоняют тот же код в Node.

## 4. Время и часы

- **Единая временная база** — аудиочасы: `кадр / sampleRate` совпадает с `AudioContext.currentTime`. Время атаки сохраняется независимо от музыкальной сетки.
- **`Transport`** отображает время в доли: `beats(t) = beatRef + (t − tRef)·bpm/60`. Отдельное поле `offset` хранит, какая доля считается «1». Ручная установка «1» поэтому не мешает автоматическому трекингу.
- **Коррекции фазы не прыгают:** `setCorrection` ставит поправку в очередь, `advance` применяет её со скоростью не более `slewRate` долей в секунду. Смена BPM сохраняет непрерывность фазы.
- **Три режима часов:** `auto` (часы ведёт трекер), `manual` (свободный ход с ручным BPM) и `reference` (только Demo: истинный темп синтезатора). Трекер работает всегда, поэтому в Demo диагностика показывает его ошибку против эталона.
- **Стрелка** рисуется по времени того, что слышно сейчас (`getOutputTimestamp`; для микрофона — `currentTime`). Расхождение со снимком сглаживается: мелкие поправки смешиваются, крупные применяются сразу.

## 5. Темп и фаза

1. **Огибающая атак** — сумма положительного потока лог-магнитуды по трём диапазонам, шаг 11,6 мс, окно 8 с.
2. **Темп** — ACF огибающей. Оценка кандидата: `ac(τ) + ½ac(2τ) + ¼ac(4τ) + ½ac(τ/2)`, поиск идёт внутри одной октавы `[bpmLo, 2·bpmLo)`. Слагаемое `ac(τ/2)` (деление на восьмые) различает настоящую долю и период 1,5 доли, характерный для тресильо, клаве и тумбао (подробно — EXPERIMENTS.md). Октаву выбирает пользователь кнопками ×2 и ÷2: неоднозначность 90/180 решается явно, а не скрыто.
3. **Захват** — 3 согласованные оценки подряд на окне не короче 5 с. Затем фаза жёстко привязывается к лучшему смещению гребёнки.
4. **Сопровождение** — каждые 0,5 с BPM сглаживается к оценке, фаза корректируется пропорционально (0,6·ошибки), темп — слабым интегральным звеном. Переход на полдоли (доля ↔ «&») разрешён, только если отклик гребёнки на новой фазе на 15% сильнее текущей и это держится 2 с.
5. **Потеря захвата** — 4 несогласованные оценки подряд или долго низкая уверенность.

Начало восьмёрки (где «1») автоматически не определяется: по ТЗ это отдельная задача. Пользователь ставит его кнопкой «Здесь 1». Корреляция с эталоном клаве в карточке слоя уже показывает вероятный сдвиг.

## 6. Накопление

### Атаки (`EventAccumulator`)
128 ячеек на цикл в каждом из 4 каналов (3 диапазона и сумма). Атака делится линейно между двумя соседними ячейками, поэтому квантизации нет и микротайминг сохраняется. Старение происходит при проходе стрелки: ячейка умножается на α = e^(−1/N), где N — память в циклах. Значит, каждое наблюдение стареет ровно один раз за цикл независимо от темпа.

### Полярная спектрограмма (`PolarSpectrogram`)
- Цикл делится на A = 256 угловых слотов. Для слота `a` цикла `c` берётся кадр FFT (Hann, N = 2048), **центрированный точно** во времени `timeAtCycleBeats(8·(c + a/A))`. Кадры привязаны к музыкальной фазе, а не к фиксированному шагу.
- Дробный сдвиг начала кадра δ компенсируется линейной фазой `X[k]·e^{+j2πkδ/N}`. Без этого комплексное накопление разрушалось бы дрожанием на долю сэмпла.
- Два аккумулятора на ячейку (слот × бин частоты):
  - `P ← αP + (1−α)|X|²` — **мощность**, некогерентное фазо-синхронное усреднение;
  - `C ← αC + (1−α)X` — **когерентное** комплексное среднее.
  - **Когерентность** `|C|²/P` ∈ [0, 1]: близка к 1 там, где цикл за циклом повторяется одна и та же форма волны.
- Отображение в дБ относительно максимума мощности. Когерентный режим использует ту же шкалу, поэтому видно, какая часть мощности «выживает».
- Тихие кадры (< −80 дБFS) не накапливаются: отсутствие сигнала — не наблюдение.
- Рендер строит таблицу «пиксель → (слот, бин)» один раз на геометрию. Радиус переводится в частоту линейно `f = u·f_max` или логарифмически `f = 40·(f_max/40)^u`, где `u = (r − r₀)/(1 − r₀)`. Так реализовано «ноль частоты на заданном сдвиге от центра».

## 7. Различение типов данных (принцип ТЗ §16)

| Тип | Где | Как показан |
|---|---|---|
| Эталон | `patterns.json`, `dance-patterns.json` | цветные/серые сегменты, метка «эталон», источник и статус в карточке |
| Наблюдение | атаки, спектрограмма | монохромные «чернила» (как сонограмма), пунктирная граница |
| Гипотеза | кандидаты темпа, корреляция с эталоном | только числа с оценками; не превращается в «распознанный инструмент» |
| Предполагаемые (IMU) | `InferredMovementEvent` | будущее: `kind: 'inferred'` |

## 8. Существенные решения

| Решение | Почему |
|---|---|
| Canvas 2D, а не SVG | Полярная спектрограмма — пиксельная карта (до 720² точек при 15 Гц); единая система отрисовки для слоёв и спектра |
| Анализ в Worker, worklet только копирует | Стабильность аудиопотока на телефонах; тот же код тестируется в Node |
| Собственная FFT вместо `AnalyserNode` | Нужны комплексные спектры для когерентного режима и кадры в точных фазовых позициях |
| Demo = чистый TS-рендер в буфер | Один и тот же сигнал в приложении и тестах; точный ground truth |
| Поиск темпа внутри октавы | Неоднозначность 90/180 явная и управляемая пользователем |
| Метрический шаблон с `ac(τ/2)` | Без него тресильо в сальсе даёт 120 вместо 180 (измерено) |
| Гистерезис доля ↔ «&» | В сальсе синкопы дают почти равный вес слабым долям (измерено) |
| Настройки в `localStorage` | Только удобство; библиотека шаблонов и сессии пойдут в IndexedDB (MVP 3–4) |
| Без внешних зависимостей DSP | Прозрачность алгоритмов, независимая замена модулей |
| `vite-plugin-pwa` не используется | Ручной `sw.js` + manifest без связки версий плагина |

## 9. Точки расширения

- **Сопоставление с рисунками (MVP 3):** `matchPattern` уже считает циклическую корреляцию. Дальше — вероятности по нескольким диапазонам, конкурирующие гипотезы, направление клаве, определение «1» по рисунку. Именно это разрешит неоднозначность доля ↔ «&», которую одна огибающая не снимает.
- **Запись и экспорт (MVP 4):** снимок уже содержит время, BPM, фазу, атаки с диапазоном и силой, версию алгоритма (`ALGORITHM_VERSION`).
- **IMU:** `src/imu/types.ts` — контракт данных и синхронизации двух телефонов.
- **Замена алгоритмов:** функции DSP чистые; движок вызывает их через узкие интерфейсы.
